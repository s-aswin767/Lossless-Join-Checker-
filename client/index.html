    Theory, algorithm and limitations

    What lossless join means

    A decomposition of R into R₁…Rk is lossless (non-additive) if for every legal instance r of R:

    πR₁(r) ⋈ … ⋈ πRk(r) = r

    The join must return exactly the original rows. A lossy decomposition returns extra spurious tuples, so information about which values belonged together is destroyed.

    The chase test

    Build a tableau with one row per sub-relation and one column per attribute. Cell (i,j) is aj when attribute Aj is in Ri, else bij.

    • For each FD X→Y, take rows that agree on all of X.
    • Equate their Y values: if any is aj, all become aj; otherwise all take the same b symbol.
    • Repeat until nothing changes.

    If any row becomes all a-symbols, the decomposition is lossless; otherwise it is lossy.

    Binary shortcut

    For exactly two fragments, the decomposition is lossless iff the common attributes form a superkey of at least one side:

    (R₁ ∩ R₂) → R₁  or  (R₁ ∩ R₂) → R₂

    Checked with attribute closure. An empty intersection always means lossy (the join degenerates to a Cartesian product).

    Complexity

    • Tableau: k × n cells for k fragments, n attributes.
    • One chase pass costs O(|F| · k · n); each pass that changes anything removes at least one distinct symbol, and there are at most k·n symbols.
    • Worst case O(|F| · k² · n²) — polynomial, and instant for classroom-sized schemas.
    • Attribute closure is O(|F| · n) per call.

    Where it is used

    • Normalization to BCNF, which guarantees losslessness but may lose dependencies.
    • 3NF synthesis, which preserves dependencies and adds a key fragment for losslessness.
    • Vertical partitioning and sharding in warehouses, where a bad split silently invents rows.
    • Data-warehouse star schemas and view design, checking a reconstructed fact table is exact.

    Limitations

    • Holds only for the FDs you supply — a missing FD can make a lossless decomposition look lossy.
    • Lossless ≠ dependency-preserving; both must be checked, and BCNF cannot always give both.
    • This chase covers FDs. With multivalued dependencies the same tableau needs the MVD chase rule (4NF).
    • Says nothing about performance, redundancy or null handling — outer joins break the guarantee.
